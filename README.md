**Overview**

This repository contains my completed submission for the WGU course **D197 – Version Control**.

The project uses a multi-page marketing website as the working codebase for demonstrating professional Git workflow. The web project itself is the vehicle; the assessed work is the version control practice applied to it — branching, isolated feature development, merging, conflict resolution, and a clean, readable commit history.

**Scenario**

A development team maintains a company website and needs changes made across several pages. Multiple changes must be developed independently and integrated without overwriting one another or destabilizing the main branch.

This requires a disciplined branching strategy, meaningful commits, and the ability to resolve conflicts when parallel changes touch the same files.

**Project Objectives**

-Initialize and configure a Git repository connected to a remote

-Create feature branches to isolate work from the main branch

-Stage and commit changes with clear, descriptive commit messages

-Merge feature branches back into the main branch

-Identify and resolve merge conflicts without losing work

-Maintain a readable commit history that documents the evolution of the project

-Use remote operations to synchronize local and hosted repositories

**Version Control Concepts Demonstrated**

**Repository Management**
Initializing a repository, configuring the remote origin, and establishing the main branch.

**Branching Strategy**
Creating dedicated branches for individual changes so that in-progress work never destabilizes the main branch, and multiple changes can proceed in parallel.

**Staging and Committing**
Selectively staging changes and writing commit messages that describe intent rather than mechanics, producing a history that is useful to read later.

**Merging**
Integrating completed feature branches back into main, including both fast-forward and three-way merge scenarios.

**Conflict Resolution**
Identifying conflicting changes when parallel branches modify the same lines, inspecting conflict markers, choosing the correct resolution, and completing the merge.

**Remote Synchronization**
Pushing local commits to the remote repository and pulling remote changes into the local working copy.

**History Inspection**
Reviewing commit history and diffs to trace when and why a change was introduced.

**The Web Project**

The codebase is a multi-page static website for a web design and digital services company, consisting of a home page, an about page, a customers page, and a contact page, supported by a shared stylesheet, JavaScript, and an image library covering service areas such as web design, SEO, e-commerce, and responsive development.

The site is intentionally straightforward. Its purpose is to provide realistic, multi-file content for branching and merging exercises rather than to serve as a front-end showcase.

**Skills Demonstrated**
